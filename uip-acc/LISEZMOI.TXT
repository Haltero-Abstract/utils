uIP tool ACC - reseau NetUSBee en arriere-plan du bureau GEM
=============================================================

Version NON OFFICIELLE, ecrite avec l'aide d'une IA (Claude), ni validee
ni maintenue par les auteurs d'uIPtool. Licences : voir LICENSE.TXT.

Base : uIPtool (Sqward / Nokturnal), depot sqward-uip-tools 0218184ebf8b
(serveur web + FTP, DHCP ou IP fixe, NetUSBee / EtherNEC).
Version accessoire : le reseau tourne pendant que le bureau GEM reste
utilisable (ouvrir des dossiers, copier des fichiers, etc.).

INSTALLATION
------------
1. Copier UIP.ACC a la racine du disque de boot (C:\UIP.ACC).
2. Redemarrer le Falcon.
3. Menu "Bureau" > "uIP tool (reseau)" : une petite fenetre s'ouvre.
   Langue automatique : francais si le TOS est francais (ou suisse
   romand), anglais sinon ("Desk" > "uIP tool (network)").

UTILISATION
-----------
[ Activer ] / [ Desactiver ]  : allume / coupe le reseau.
[DHCP/Fixe]                   : bascule DHCP <-> IP fixe (lue dans UIP.CFG).
La fenetre affiche l'adresse IP : la taper dans le navigateur du PC
(http://IP) ou se connecter en FTP (port 21, mode PASSIF, login quelconque).

L'etat Actif/Inactif est memorise dans C:\UIPACC.INF : si le reseau etait
actif, il redemarre tout seul au prochain boot.
La configuration IP est dans C:\UIP.CFG (meme format que uip.tos) :
   <0=DHCP|1=fixe> 0 0 <ip> <masque> <passerelle>

A SAVOIR
--------
- Le reseau tourne tant que le GEM tourne (bureau ou programme GEM).
  Quand un jeu ou un programme TOS prend toute la machine (RICK3D...),
  le reseau est simplement en pause et reprend au retour au bureau.
- L'execution a distance (bouton "run" de l'interface web, uip-run.py)
  est desactivee dans la version accessoire : utiliser UIP.TOS pour ca.
- Pendant une alerte disque ("lecteur A: ne repond pas"), le reseau se met
  en pause (GEMDOS n'est pas re-entrant).
- Ne pas utiliser avec STiK/STinG, ni sous MiNT (comme uip.tos).
- Debit plus faible que UIP.TOS plein ecran (le reseau est servi entre
  deux evenements GEM, toutes les 20 ms).
- Si une copie est en cours et qu'on lance un programme qui garde la main,
  le transfert reste en attente : attendre la fin des transferts avant de
  lancer un jeu.

FICHIERS
--------
UIP.ACC        accessoire (a mettre en C:\)
UIP.TOS        uIPtool classique plein ecran, recompile a partir des memes
               sources (optionnel)
TEST\UIP_TEST.ACC  version de test avec carte reseau SIMULEE (pour Hatari) -
               ne pas utiliser sur le Falcon.
SOURCES\       sources completes + Makefile.acc

RECOMPILER
----------
Toolchain m68k-atari-mintelf-gcc 13 + libcmini 0.54 compilee avec
-fleading-underscore (voir en-tete de Makefile.acc) :
   sh gen_ui.sh
   make -f Makefile.acc LIBCMINI=/chemin/libcmini

Fichiers ajoutes / modifies par rapport a uIPtool :
   src/acc.c       fenetre GEM, boucle evnt_multi + timer
   src/accgem.c/.h liaisons AES/VDI minimales
   src/acccrit.s   protection etv_critic (alertes disque)
   src/uipacc.h    interface accessoire <-> pile uIP
   src/accshim.h   printf de la pile redirige vers la fenetre
   src/main.c      fonctions uipacc_start/step/stop (#ifdef UIP_ACC)
   src/atari_http_server/httpd.c  "run" desactive en accessoire
   src/compat/inttypes.h, Makefile.acc, gen_ui.sh

Teste sous Hatari 2.6.1 (Falcon, EmuTOS 512k FR, VGA) : chargement,
fenetre, bureau utilisable reseau actif, boutons, lancement d'un programme
et retour, alerte disque. Hatari n'emule pas la NetUSBee : le dialogue
reseau reel reste a valider sur le Falcon.
